What it produces

Useful output, already organized.

Docforge inspects the repository context you select and writes predictable Markdown artifacts back to the project.

Developer reference

Setup, architecture, APIs, extension points, configuration, and testing in docs/DEVELOPER.md.

User guide

Features, task-oriented instructions, examples, and troubleshooting in docs/USER_GUIDE.md.

NotebookLM source

A combined, attributed source in docs/NOTEBOOKLM.md, with optional direct upload.

Quick install

Add it from the project root.

The installer adds Docforge as vendor/docforge, creates configuration, and installs the workflow.

Terminal
curl -fsSL https://raw.githubusercontent.com/nikolareljin/docforge/main/install.sh | bash

# review generated configuration before committing
git diff -- .gitmodules .docforge.yml .github/workflows/docs.yml

Review remote scripts before piping them to a shell. The manual submodule installation provides the same result step by step.

Provider choice

Hosted, local, or compatible.

The default GitHub Models provider uses the workflow token. Other providers use their own secret or local endpoint.

Zero-secret default

GitHub Models receives GITHUB_TOKEN automatically from the Actions runner.

Hosted alternatives

Use Groq, Anthropic, Together, OpenRouter, Bedrock, or an OpenAI-compatible endpoint.

Local inference

Choose Ollama for local runs where repository context must stay on your machine.
